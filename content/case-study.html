In-car voice assistants can now open a web page, and for most of them that is the only thing they can do with the browser. Voiceboard is what we built with that single control: games the assistant hosts by voice while the screen keeps score, running as a WordPress plugin on voiceboard.wpengine.com.

It's a small project, but it leans on the same parts of WordPress that run much larger sites, which is the point of writing it up.

One URL per screen

The assistant asks the questions, judges the answers, and opens a new URL whenever the screen should change; the page draws whatever the query string describes. A trivia question:

/board/?g=trivia&st=ask&t=Space&n=3&of=10
  &q=Which+planet+has+the+most+known+moons%3F
  &c=Jupiter|Saturn|Uranus|Neptune&p=Joe:200,Sam:100&timer=15

That link draws the question, four choices, both scores, and a countdown that runs on its own. Swap in st=reveal&a=B&r=Sam and Saturn turns green with Sam's name under it. Each of these is a complete screen:

  • Space trivia with a countdown
  • Name that movie in emoji
  • A Jeopardy-style board mid-game
  • A Daily Double
  • A six-player finale with confetti

Since a URL fully describes its screen, there's nothing to install and a reload never loses the game. Assistants write messy URLs, so the page is forgiving: it decodes values encoded twice, accepts an answer as B, 2, or Saturn, and falls back to the home screen for a game it doesn't know.

Teaching the assistant the rules

Nobody should have to read a prompt aloud before a road trip, so the site explains itself. The rules live in one file, llms.txt, which the plugin serves at /llms.txt and embeds in the board's HTML for tools that don't run JavaScript, filled in with the domain the visitor used.

The home page redirects to the board, so all a person says is "Open voiceboard.wpengine.com and host trivia," the same sentence the board displays.

Three design decisions

Touch never changes the game

Passengers can tap to browse games, switch between the default and Cyber themes, or go fullscreen, but questions, scores, timers, and effects belong to the assistant, so the screen and the host can never disagree. Tap-to-answer waits until taps have a way back to the assistant.

Each kind of state has one home

The first two are enough to play. The device remembers the roster, so after the first question the assistant sends only changes like add=Sam:100, and reopening a URL never counts a change twice. WordPress holds what one browser can't share (a transcript the assistant can read back, and a log of the URLs assistants really send), and Presence answers who is playing right now.

Features grow with the assistant

Each level adds to the one before and depends on nothing above it.

  1. An assistant that can open a URL gets the full game on screen, which is what in-car assistants can do today.
  2. One that can also read a URL gets the transcript and never has to keep score in its head.
  3. One that can call tools over MCP drives the game with structured abilities while the board follows along.

Why WordPress

Every server-side piece a car game board needs turns out to be something WordPress already has. Most of these have run in production for years; Presence and Abilities are newer, built on the same hooks and data model.

  • Routing happens on parse_request, before the main query, so board parameters such as p= (players) are never mistaken for a post ID and there are no rewrite rules to flush.
  • A game session is a document with a title, a body, and metadata, which is a post, so a voiceboard_session post type gets admin screens, capabilities, export, and REST access without a new table.
  • A REST endpoint receives each page view and serves the transcript, and WP-Cron prunes old sessions.
  • The Presence API feature plugin stores short-lived entries in its own wp_presence table, so a car that stops pinging simply expires; without the plugin, you lose "who's online" and nothing else.
  • The Abilities API, in core since 6.9 (this site runs 7.1), and the MCP Adapter let tool-calling assistants run a game with abilities like voiceboard/add-score instead of URLs.

Deploying is ordinary WordPress: the plugin works the moment it's activated, and because state lives in the query string, the board's HTML is a static shell that a managed host's page cache serves well.

Free games for anyone with a voice and a screen

Anyone with a conversational assistant and a screen with a browser gets a game show host and several games for free, whichever assistant they use and whatever language they speak. Questions and names appear as the assistant sends them, the board's own labels come in nine languages, and Arabic and Hebrew lay out right to left.

The assistant reads everything aloud, so playing takes no more than a glance at the scores, which opens it to kids who can't read fluently yet, older adults who would rather talk than tap, and people with limited mobility. On screen, the type is large, the colors follow the device's light or dark setting, the countdown is marked as a timer for screen readers, and confetti stays off when reduced motion is on.

How it's built and shipped

A Playwright suite runs twice on every push, once against the static files and once against the plugin inside WordPress Playground, and only a passing run deploys to the live site. Release Please turns conventional commits into versioned releases with a changelog and a plugin zip.

Where it stands

Shipped: trivia, a Jeopardy-style board, two themes, labels in nine languages with right-to-left layout, the timer and confetti, the remembered roster and Hall of Fame, and the plugin with llms.txt, the home redirect, and continuous deployment.

Designed but not built: sessions and transcripts, the URL log, presence, and the MCP abilities.

Not yet tested: a real assistant in a real car. Whether an in-car assistant reads the instructions on its own, how reliably it writes URLs over a long game, and whether reopening a URL reuses the tab are open questions; the URL log is built to answer them, and we'll publish what it shows.

Next come more games (road trip bingo, a drawing game, a blur-to-reveal round), tap-to-answer, and an abilities-first mode for assistants that speak MCP.

The source is on GitHub. The design is inspired by in-car interfaces, and the project isn't affiliated with any carmaker.
