In-car voice assistants can now open a web page, and for most of them that is the only thing they can do with the browser. Voiceboard is what we built with that single control: games the assistant hosts by voice while the screen keeps score, running as a WordPress plugin on voiceboard.wpengine.com.

This post covers how it works, the decisions behind it, why WordPress fits, and what isn't built yet.

One URL per screen

The assistant is the host: it asks the questions, judges the answers, and opens a new URL whenever the screen should change. The page draws whatever the query string describes. A trivia question looks like this:

/board/?g=trivia&st=ask&t=Space&n=3&of=10
  &q=Which+planet+has+the+most+known+moons%3F
  &c=Jupiter|Saturn|Uranus|Neptune&p=Joe:200,Sam:100&timer=15

That one link shows the question, four lettered choices, the progress, both scores, and a 15-second countdown that runs on its own. Swap in st=reveal&a=B&r=Sam and Saturn turns green with Sam's name under it. Each of these is a complete screen, exactly as an assistant would open it:

  • Space trivia with a countdown
  • Name that movie in emoji
  • A Jeopardy-style board mid-game
  • A Daily Double
  • A six-player finale with confetti

The browser is the whole runtime, so there's nothing to install or pair, and because a URL fully describes its screen, a reload never loses the game. Assistants write messy URLs, so the page forgives them: it decodes values encoded twice, accepts an answer as B, 2, or Saturn, and opens the home screen for a game it doesn't know.

Teaching the assistant the rules

Nobody should have to read a prompt aloud before a road trip, so the site explains itself. The hosting rules live in one file, llms.txt, which the plugin serves at /llms.txt and also embeds in the board's HTML for tools that read pages without running JavaScript, each time with the board URL of whatever domain the visitor typed.

The home page redirects to the board, so the instruction a person gives is a single sentence: "Open voiceboard.wpengine.com and host trivia." The board shows that sentence on screen, too.

Three design decisions

Touch never changes the game

Passengers can tap to browse games, switch between the default and Cyber themes, or go fullscreen, but questions, scores, timers, and effects belong to the assistant, so the screen and the host can never disagree. Tap-to-answer waits until taps have a way back to the assistant.

Each kind of state has one home

The URL and localStorage are enough to play: the device remembers the roster, so after the first question the assistant sends only changes like add=Sam:100, and reopening a URL never applies a change twice. WordPress keeps what one browser can't, a transcript the assistant can read back and a log of what assistants actually send, while Presence answers a single question: who is playing right now.

Features grow with the assistant

  1. An assistant that can open a URL gets the full game on screen, which is what in-car assistants can do today.
  2. One that can also read a URL gets the transcript and never has to keep score in its head.
  3. One that can call tools over MCP drives the game with structured abilities while the board follows along.

No level depends on the one above it.

Why WordPress

A car game board is an unusual WordPress project, yet every server-side piece it needs is a WordPress primitive. Most have run in production for years; Presence and Abilities are newer and sit on the same foundations.

  • Routing happens on parse_request, before the main query, so board parameters such as p= (players) are never mistaken for a post ID and there are no rewrite rules to flush.
  • A game session is a document with a title, a body, and metadata, which is a post, so a voiceboard_session post type gets admin screens, capabilities, export, and REST access without a new table.
  • WP-Cron prunes old sessions, and a small REST endpoint receives each page view and serves the transcript.
  • The Presence API feature plugin stores short-lived entries in its own wp_presence table, so a car that stops pinging simply expires; without the plugin, you lose "who's online" and nothing else.
  • The Abilities API, in core since 6.9 (this site runs 7.1), and the MCP Adapter let tool-calling assistants run a game with abilities like voiceboard/add-score instead of URLs.

Deploying is ordinary WordPress: the plugin works the moment it's activated, and because state lives in the query string, the board's HTML is a static shell that a managed host's page cache serves well.

Free games for anyone with a voice and a screen

Anyone with an assistant that can hold a conversation and a screen with a browser gets a game show host and several games at no cost, and the board doesn't care which assistant opens the URL.

Because the assistant reads everything aloud, playing asks for nothing more than a glance at the scores. That includes kids who can't read fluently yet, older adults who would rather talk than tap, and people with limited mobility. The board uses large type, follows the device's light or dark setting, announces changes to screen readers, and skips the confetti when reduced motion is on.

How it's built and shipped

A Playwright suite runs twice on every push, once against the static files and once against the plugin inside WordPress Playground, and only a passing run deploys to the live site. Release Please turns conventional commits into versioned releases with a changelog and a plugin zip.

Where it stands

Shipped: trivia and a Jeopardy-style board, two themes, the timer and confetti, the remembered roster and Hall of Fame, the plugin with llms.txt and the home redirect, and continuous deployment.

Designed but not built: sessions and transcripts, the URL log, presence, and the MCP abilities.

Not yet tested: a real assistant in a real car. We don't know whether an in-car assistant reads the instructions on its own, how reliably it writes these URLs over a long game, or whether reopening a URL reuses the same tab. The URL log is meant to answer those questions, and we'll write up what it shows.

Next come more games (road trip bingo, a drawing game, a blur-to-reveal round), tap-to-answer, and an abilities-first mode for assistants that speak MCP.

The source is on GitHub. The design is inspired by in-car interfaces, and the project isn't affiliated with any carmaker.
